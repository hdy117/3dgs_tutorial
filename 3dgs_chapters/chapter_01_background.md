一张总导航（类比 → 基石 → 做错时症状）：

| 概念 | 一个够用的生活画面 | 基石一句话 | 做错时常见症状 |
|------|-------------------|------------|----------------|

| 3DGS 跳跃 | 显式软印章可投影可混合 | 显式 Gaussian + splat 换掉海量 MLP 查询 | 当成「NeRF 小补丁」理解会偏 |

## 一、定界问题：View Synthesis 的本质

### 1.1 一个非常生活化的场景

你用手机绕着房间走了一圈，拍了大约 20～100 张照片。现在你想：

- 蹲下来仰视天花板的角度（你没拍过）
- 稍微往左平移半步的视角（你也没刚好站在那儿）
- 甚至做一段「镜头慢慢推近桌子」的虚拟运镜

问题不是「把已有照片再滤镜美化一下」，而是：

> **在从未拍摄过的相机位姿上，生成一张看起来像真的拍出来的图。**

这就是 **novel view synthesis**（新视角合成 [novel view synthesis]），也常被放在更大的 **image-based rendering / neural rendering** 版图里。

### 1.2 形式化：输入输出分别是什么？

$$
\text{输入: } \{(I_m, C_m)\}_{m=1}^{M}
\quad\Longrightarrow\quad
\text{输出: 任意新相机 } C_{\text{new}} \text{ 对应的图像 } I_{\text{new}}
$$

- \(I_m\)：第 \(m\) 张已知照片（2D 像素阵列）
- \(C_m\)：**camera parameters**（相机参数 [camera parameters]）——没有它，照片只是一张「不知从哪看的像素地毯」
- 目标：学会一个可渲染的 3D（或 2.5D）场景表示，使新视角可查询

可以画成：

```text
  照片1 + 相机1 ──┐
  照片2 + 相机2 ──┼──▶  某种场景表示 S  ──▶  render(S, C_new) = I_new
  ...             │
  照片M + 相机M ──┘
```

**第一性原理提醒**：你真正要学的不是「照片本身」，而是一个能解释这些照片的 **3D 场景函数**——至少要能回答：沿每条视线，颜色如何累加而成。

#### 生活类比（必须映射回基石）

把 **novel view synthesis** 想成「你已经绕房间拍了一圈，现在要让计算机补出你没站过的那个机位」。

| 生活画面 | 对应基石 |
|----------|----------|
| 朋友问：「从茶几左前方看，墙上画是什么样？」——你没拍过那张 | 输出是任意新相机 \(C_{new}\) 的图像 \(I_{new}\) |
| 相册美颜滤镜只改已有像素 | **不是** view synthesis；缺 3D/多视图几何 |
| 带着「每张照片是从哪拍的」标签的相册 | 输入必须是 \(\{(I_m, C_m)\}\)，不是裸图 |
| 脑内建了房间模型再「想象」新角度 | 真正要学的是可查询的场景表示 \(S\)，再 `render(S, C_new)` |

```text
错误故事：把 20 张照片拼成全景，再拉伸变形「假装」新视角
  → 那是 2D 拼贴，换高度/绕到背面立刻穿帮

正确故事：从多视图恢复「可渲染的 3D 解释」，再开新相机
```

> 映射回基石：view synthesis 的定义是 **已知多视图 → 任意新位姿图像**；核心是场景表示 + 渲染，不是单图滤镜。

#### 失败对照：做对 vs 做错

| 场景 | 做对 | 做错时你看到什么 |
|------|------|------------------|
| 定义任务 | 明确 \(C_{new}\) 与训练视角不同 | 只在训练视角上拟合 → 过拟合相册，不是新视角 |
| 输入 | 每张图配上可靠 pose | 只有图没有 \(C_m\) → 几何欠定，经典 3DGS 几乎玩不转 |
| 评价 | 在 held-out 视角比 PSNR/SSIM/LPIPS | 只看训练视角 loss 很低 → 误以为「已经会飞」 |
| 心智 | 「学 3D 解释」 | 「学怎么糊弄这几张图」→ 一换机位墙穿模、地板漂 |

```text
症状速记：
  「训练图很美，新视角糊/飞」 → 可能没在做真正的 multi-view 几何约束
  「像全景拉伸」             → 把 2D 图像变形当成了 3D view synthesis
```

### 概念卡：Camera Intrinsics & Extrinsics（相机内参与外参）

#### English name
**camera intrinsics**（内参矩阵常写 **K**），**camera extrinsics**（外参，常写 **[R|t]** 或 world-to-camera pose）

#### 中文通俗说法
- 内参 [intrinsics]：这台相机自己的「镜头与传感器几何」——焦距、主点等。  
- 外参 [extrinsics]：相机在世界中的位姿——朝哪看、站在哪。

#### Origin（起源）
多视图几何被迫区分两类量：换镜头会变的量，与挪相机位姿会变的量。没有这种拆分，就无法把像素反投影成 3D ray（射线 [ray]）。

#### Core idea（核心思想）

**Intrinsics K（常见针孔模型）**：

$$
K =
\begin{bmatrix}
f_x & 0 & c_x \\
0 & f_y & c_y \\
0 & 0 & 1
\end{bmatrix}
$$

- \(f_x, f_y\)：以像素为单位的 focal length（焦距 [focal length]）
- \(c_x, c_y\)：principal point（主点 [principal point]），常靠近图像中心

**Extrinsics**：把 world point 变到 camera frame：

$$
\mathbf{p}_{\text{cam}} = R \, \mathbf{p}_{\text{world}} + \mathbf{t}
$$

- \(R \in SO(3)\)：rotation matrix（旋转矩阵），满足 \(R^{\top}R=I\) 且 \(\det R=1\)
- \(\mathbf{t}\)：translation；在此约定下，相机中心（camera center）在世界系中为 \(\mathbf{C} = -R^{\top}\mathbf{t}\)

**像素 → 射线**（后续所有 volume rendering / ray marching 的入口）：

```text
像素 (u,v)
  → 相机坐标系方向 d ∝ Rᵀ K⁻¹ [u,v,1]ᵀ
  → 射线 r(t) = C + t · d ,  t > 0
```

#### Why not alternatives（为何不是别的）
- 只有照片没有 pose：几何上严重欠定（当然也有 pose-free 研究，但那是另一条更难的线）。
- 用「拍的人的感觉」描述视角：机器无法计算。
- 忽略畸变 [distortion]：广角场景会系统性对不齐（实践中常先标定/去畸变）。

#### In 3DGS（在 3DGS 里干什么）
训练与推理都依赖已知（或 SfM 恢复的）相机参数：  
Gaussian 要投到正确的像素位置；loss 才能和 ground-truth 图像对齐。数据准备章会回到 COLMAP 等工具。

#### Worked example / PyTorch

```python
import torch

def pixel_to_ray_dir(u, v, K, R):
    """Return a camera-to-world ray direction (not normalized)."""
    fx, fy = K[0, 0], K[1, 1]
    cx, cy = K[0, 2], K[1, 2]
    x = (u - cx) / fx
    y = (v - cy) / fy
    d_cam = torch.tensor([x, y, 1.0])
    # world direction
    d_world = R.T @ d_cam
    return d_world / torch.norm(d_world)

K = torch.tensor([[800., 0., 320.],
                  [0., 800., 240.],
                  [0., 0., 1.]])
R = torch.eye(3)
print(pixel_to_ray_dir(320., 240., K, R))  # 光轴附近，约 [0,0,1]
```

#### Common confusions（易混点）
1. **OpenCV / OpenGL / COLMAP 坐标系约定不同**（y 向上还是向下、相机看 +Z 还是 -Z）。调通可视化前先确认约定。  
2. **t 与相机中心 C 不是同一个东西**。  
3. **内参是相机属性，外参是这次拍照的位姿**——换位置只改外参。

#### 生活类比（必须映射回基石）

把 **intrinsics** 想成「这台相机出厂时的身份证」，把 **extrinsics** 想成「这一次拍照时你站哪、脸朝哪」。

| 生活画面 | 对应基石 |
|----------|----------|
| 换广角镜头：同样姿势，画面变「更宽」 | 改 \(K\)（\(f_x,f_y,c_x,c_y\)），外参可不变 |
| 人没动镜头，只是往左挪半步再拍 | 改 \([R\|t]\)，内参通常不变 |
| 用像素坐标反推「朝哪个方向看过去」 | \(d \propto R^\top K^{-1}[u,v,1]^\top\) |
| 导游地图上的「你在这里」箭头 | 外参决定射线起点与朝向；没有它照片只是像素地毯 |

更贴 3DGS 的画面：

```text
内参 K：这台手机传感器 + 镜头的「尺子」
外参：这张训练照片当时相机在世界坐标系里的位姿
Gaussian 中心 μ 要投到「这张真值图」的正确像素上
  → 尺子错了 / 站位错了，loss 会对着错误几何较劲
```

> 映射回基石：内参描述成像几何；外参描述 world→camera 刚体变换；两者合起来才把像素变成 3D ray。

#### 失败对照：做对 vs 做错

| 操作 | 做对 | 做错与症状 |
|------|------|------------|
| 换机位 | 只更新外参 | 误改焦距「硬凑」对齐 → 深度与尺度全歪 |
| 坐标系 | 统一 COLMAP/OpenCV/OpenGL 约定 | y 轴上下反、看 +Z/-Z 混用 → 场景躺倒/镜像 |
| \(t\) 与 \(C\) | 分清 translation 与 camera center | 把 \(t\) 当相机中心直接用 → 射线起点错 |
| 训练数据 | SfM 位姿检查可视化 | 位姿噪声大 → Gaussian 怎么优化都对不齐，漂、重影 |

```text
症状速记：
  「整场景躺平或镜像」 → 坐标系/旋转约定
  「永远对不齐 GT」   → 内参尺度或外参 t 语义错
```

### 1.3 三个关键约束（这是本质，不是细节）

| 约束 | English | 含义 | 对算法的压力 |
|------|---------|------|--------------|
| 稀疏输入 | sparse multi-view | 通常只有几十到几百张图 | 不能假设稠密扫描 |
| 稠密输出 | dense image output | 新视角必须是完整连续图像 | 表示要能填洞、抗锯齿 |
| 实时性（可选但关键） | real-time rendering | AR/VR/交互需要 ≥30–60 FPS | 推理必须快 |

再加一个隐含约束：**可学习 / 可优化**——表示最好能用 gradient 去拟合照片（第 0 章的工具在这里上场）。

三角张力可以画成：

```text
            质量 quality
             /        \
            /          \
           /            \
          /              \
      速度 speed ←——→ 内存 memory
```

残酷事实：三代以前的方法很难三者同时漂亮。每一代都在三角上挪动妥协点；上一代的遗留痛点，就是下一代的突破口。

## 二、拆基石：渲染到底在积分什么？

在深入 voxel / NeRF / 3DGS 之前，先把「一张像素颜色从哪来」说清楚。否则你会觉得各方法在比实现技巧，而不是在比 **如何存储同一个物理量**。

### 2.1 Volume Rendering Equation（体积渲染方程）

对一条射线 \(r(t) = \mathbf{o} + t\mathbf{d}\)：

$$
C(r)=\int_{t_n}^{t_f} T(t)\,\sigma(r(t))\,c(r(t),\mathbf{d})\,dt
$$

其中 transmittance（透射率 [transmittance]）：

$$
T(t)=\exp\left(-\int_{t_n}^{t}\sigma(r(s))\,ds\right)
$$

人话拆解：

| 符号 | English | 人话 |
|------|---------|------|
| \(\sigma\) | density | 这里有多「实」：0≈空气，很大≈几乎挡住 |
| \(c\) | radiance / color | 这里往眼睛方向「吐」什么颜色 |
| \(T(t)\) | transmittance | 从相机走到这里，还剩多少光没被前面吃掉 |
| 积分 | integration along ray | 把沿途贡献加起来，并考虑遮挡 |

```text
相机 ────────────────────────────────────────▶ 远处
  |--空气--|--薄雾--|--表面高密度--|--后面被挡住--|
  T≈1        T下降      贡献大颜色      贡献≈0
```

### 2.2 所以「场景表示」真正要存的是什么？

> **如何存储（并查询）场：** \(\sigma(\mathbf{x})\) 与 \(c(\mathbf{x},\mathbf{d})\)。

不同存储方式 → 不同的内存、速度、质量、可编辑性。  
后面所有「体素 / 点云 / MLP / Gaussian」之争，都是这场存储战争的不同战术。

离散实现时常写成 alpha compositing（与 3DGS 的 alpha blending 同源思想）：

```python
# 伪代码：沿射线从近到远
C = 0.0
T = 1.0
for sigma, color, dt in samples_front_to_back:
    alpha = 1.0 - exp(-sigma * dt)
    C += T * alpha * color
    T *= (1.0 - alpha)
    if T < 1e-4:
        break
```

#### 生活类比（必须映射回基石）

把 **volume rendering** 想成「透过一层层雾和玻璃看向远方：前面会挡住后面，沿途颜色会被透射率打折」。

| 生活画面 | 对应基石 |
|----------|----------|
| 浓雾里有一盏红灯：走近时雾先变白再看到红 | \(\sigma\) 大的地方贡献大，且降低后面的 \(T\) |
| 玻璃叠玻璃：后面景物变淡 | transmittance \(T(t)=\exp(-\int\sigma)\) |
| 从近到远把「看得见的颜料」叠起来 | 积分 \(C=\int T\sigma c\,dt\) 或离散 alpha compositing |
| 场景表示 = 雾/颜料存放的说明书 | 存的是场 \(\sigma(x)\)、\(c(x,d)\)，不是直接存整张图 |

```text
相机眼睛 ──薄空气── 薄纱帘 ── 实心桌面 ── (后面被挡住)
   T≈1        T下降      贡献大颜色         贡献≈0
```

> 映射回基石：像素颜色是沿射线的 **加权积分**；权重由密度与累积透射率共同决定。体素/NeRF/3DGS 之争，是「如何存与查 \(\sigma,c\)」之争。

#### 失败对照：做对 vs 做错

| 场景 | 做对 | 做错时你看到什么 |
|------|------|------------------|
| 积分方向 | 前到后（或一致约定）并更新 \(T\) | 顺序乱 → 遮挡关系错，前景变「透明幽灵」 |
| 离散步进 | \(\alpha = 1-e^{-\sigma\Delta t}\)，合理 \(\Delta t\) | 步长过大 → 漏掉薄结构；过小 → 极慢 |
| early stop | \(T\) 很小时截断 | 从不截断 → 浪费算力；乱截断 → 背景渗色 |
| 心智 | 「沿射线累加贡献」 | 以为「取最近点颜色」→ 体积感与半透明全无 |

```text
症状速记：
  「像 X 光透视、前后糊」 → T/顺序或 alpha 公式错
  「只有表面硬切」       → 退化成表面拾取，不是 volume integration
```

## 三、重建尝试 #1：Voxel（体素）——第一直觉，撞上立方墙

### 概念卡：Voxel Grid

#### English name
**voxel**（volume element），**voxel grid**

#### 中文通俗说法
体素 [voxel]：3D 版的 pixel——把空间切成小方块，每块存 density / color 等。

#### Origin（起源）
2D 图像是 pixel grid，医学 CT/游戏体积雾很自然地推广到 3D grid。查询简单：索引 + 三线性插值 [trilinear interpolation]。

#### Core idea（核心思想）

```text
场景 ≈ 三维数组 V[i,j,k] = (σ, r, g, b)
渲染 ≈ 沿射线 ray marching，反复查表插值，再做 volume integration
```

优点直观：

- 实现像「3D 数组」
- 查询接近 O(1)
- 好理解、好可视化

#### Why not alternatives（为何先想到它）
在还没被内存毒打前，它是最符合「图像直觉」的推广。问题不在于「它不工作」，而在于 **分辨率一高就不可扩展**。

#### In 3DGS（在 3DGS 里干什么）
3DGS 本身不是体素方法，但历史对照极重要：3DGS 选择 **稀疏粒子式 primitive**，正是为了躲开 \(V^3\) 内存墙。某些加速结构/哈希网格（如 Instant-NGP）仍可看作「体素思路的现代变体」。

#### Worked example：内存怎么爆的

设每体素 16 bytes（粗略：σ + RGB）。

| 分辨率 \(V\) | 体素数 \(V^3\) | 约内存 |
|-------------|----------------|--------|
| 128 | \(2.1\times10^6\) | ~30+ MB 量级（视通道而定） |
| 256 | \(1.7\times10^7\) | 数百 MB |
| 512 | \(1.3\times10^8\) | ~2 GB 级 |
| 1024 | \(1.1\times10^9\) | 十余 GB 级 |

关键规律：

> **\(V\) 翻倍 → 体素数 ×8。** 这是 3 维空间的数学必然，不是工程没写好。

#### Common confusions（易混点）
1. **稀疏体素结构（octree 等）** 能缓解，但查询变复杂，大范围高分辨率仍痛。  
2. **空空间浪费**：真实场景物体往往只占一小部分体积，却要为整箱空气付内存。  
3. **不是「体素不能出好图」**，而是「好图 + 大场景 + 消费级 GPU」三者冲突。

#### 生活类比（必须映射回基石）

把 **voxel grid** 想成「用整箱泡泡纸把房间塞满：每一小格都占地方，哪怕格子里是空气」。

| 生活画面 | 对应基石 |
|----------|----------|
| 2D 照片是像素格 → 3D 就再加一维格 | \(V[i,j,k]\) 存 \(\sigma,c\) |
| 分辨率从 256 提到 512：泡泡纸体积 ×8 | \(V\to 2V \Rightarrow\) 体素数 \(\times 8\) |
| 空客厅也要买满箱填充物 | 空空间税：为空气付内存 |
| 查「某坐标有没有东西」= 查格子索引 | 查询近 O(1)，但存储是 \(O(V^3)\) |

> 映射回基石：均匀笛卡尔网格覆盖体积 ⇒ 内存立方增长是数学必然，不是「实现没写好」。

#### 失败对照：做对 vs 做错

| 场景 | 做对 | 做错时你看到什么 |
|------|------|------------------|
| 提分辨率 | 先估 \(V^3\times\) bytes | 盲目 1024³ → OOM / 无法训练 |
| 大场景 | 承认稠密体素不扩展 | 硬上街区级网格 → 磁盘与带宽先死 |
| 空空间 | 考虑稀疏结构或换表示 | 坚持满数组 → 细节与显存两头不讨好 |
| 诊断 | 区分「格子太粗」与「算法错」 | 边缘永远糊却只调学习率 → 卡在表示分辨率上限 |

```text
症状速记：
  「显存随分辨率立方涨」 → 正常，这就是 V³
  「只有低分辨还行」     → 稠密体素结构性天花板
```


### 3.1 第一性结论

从公理「均匀笛卡尔网格覆盖体积」出发，必然推出立方增长。  
因此单纯稠密 voxel 很难成为通用实时新视角方案的终点。

**遗留问题（传给下一代）**：

> 大部分空间是空的，为什么还要为空气付钱？

## 四、重建尝试 #2：Point Cloud（点云）——稀疏的胜利，零维的诅咒

### 概念卡：Point Cloud

#### English name
**point cloud**

#### 中文通俗说法
点云 [point cloud]：只存「有东西的地方」的一组 3D 点（常带颜色），不存大片空气。

#### Origin（起源）
**SfM**（Structure from Motion，运动恢复结构）与 **MVS**（Multi-View Stereo）从多照片恢复三维点，是经典视觉管线。既然表面附近才有观测，稀疏点集非常自然。

#### Core idea（核心思想）

$$
p_i = (\mathbf{x}_i, c_i), \quad \mathbf{x}_i\in\mathbb{R}^3,\; c_i\in[0,1]^3
$$

内存从 \(O(V^3)\) 变成 \(O(N)\)，且通常 \(N \ll V^3\)。

```text
体素：整箱泡泡纸都买回家
点云：只把贴在物体表面的贴纸存下来
```

#### Why not alternatives（为何它能接住体素的班）
- 直接对齐「表面稀疏」的真实观测
- 与 COLMAP 等工具链无缝衔接
- 可随场景复杂度增加点数，没有 \(V^3\) 硬天花板那么僵

#### In 3DGS（在 3DGS 里干什么）
3DGS 几乎总是从 SfM 点云 **初始化** Gaussian 中心。可以理解为：

> 点云提供「骨架位置」；Gaussian 再给每个点长出体积、透明度和外观。

#### Common confusions（易混点）
1. 点云质量差（噪声、漏洞）会拖累后续拟合。  
2. 点有颜色 ≠ 已解决新视角；渲染模型仍缺失。  
3. 「加点」不能从本质上消灭 0 维问题，只能减轻。

#### 生活类比（必须映射回基石）

把 **point cloud** 想成「只在物体表面贴了一堆彩色图钉：省地方，但图钉没有面积」。

| 生活画面 | 对应基石 |
|----------|----------|
| 不再买整箱泡泡纸，只存「有东西」的位置 | 内存 \(O(N)\)，\(N\ll V^3\) |
| 图钉投到照片上 ≈ 针尖 | 0-dimensional：投影近 0 面积 |
| 相机射线很难「精确扎中」图钉 | sampling gap / coverage problem |
| 3DGS 用 SfM 点当骨架，再让每个点「长肉」 | 点提供 \(\mu\) 初始化；Gaussian 补体积 |

```text
屏幕你希望：          只画点时：
████████████          █ · █  · █
████████████          · █ · █ · ·
```

> 映射回基石：稀疏赢在存储；0 维 primitive 与 2D 像素面积需求维度不匹配，空洞是结构性的。

#### 失败对照：做对 vs 做错

| 场景 | 做对 | 做错时你看到什么 |
|------|------|------------------|
| 提质量 | 给点局部体积/连续核 | 只猛加点 → 高分辨率仍针孔、闪烁 |
| 多视图 | 几何在 3D 定义再投影 | 纯屏幕贴斑 → 换视角穿帮 |
| 初始化 | 检查 SfM 点噪声与漏洞 | 坏点云直接训 → 漂、飞点、孔洞遗传 |
| 诊断 | 「覆盖失败」vs「颜色错」 | 到处加点却不改 primitive → 永远像胡椒面 |

```text
症状速记：
  「像星空/撒盐」     → 0-D coverage
  「换视角闪烁」     → 命中图案随视角变
  「2D 贴斑多视图裂」→ 几何没锁在 3D
```


### 4.1 新的致命伤：Sampling / Coverage 空洞

点是 **0-dimensional**。投影到屏幕仍接近 0 面积。相机射线与点「精确命中」的概率极低。

```text
屏幕上你希望：          只画点时：
████████████            █ · █  · █
████████████            · █ · █ · ·
████████████            █ · · · █ ·
```

这就是 **sampling gap / coverage problem**（采样间隙 / 覆盖问题）：  
点云知道「哪里可能有表面」，但不知道「表面局部有多大、朝哪延伸」。

### 4.2 给点加体积的失败尝试（很重要的思想实验）

| 方案 | English | 做法 | 主要问题 |
|------|---------|------|----------|
| 点精灵 | point sprites | 每点画固定小片 | 透视/厚度易错，假 |
| 屏幕高斯 | 2D Gaussian splatting（仅屏幕） | 在 2D 画椭圆 | 缺 3D 约束，换视角穿帮 |
| 网格重建 | mesh / Poisson reconstruction | 先建表面再渲染 | 慢、难可微优化、编辑重 |

**核心矛盾**：

> 我们需要「有体积/面积贡献」的东西来填像素，但必须在 **3D 里定义几何**，再投影到 2D——否则 multi-view 一致性会崩。

**遗留问题**：

> 如何保持点云的稀疏性，同时在 3D 给出连续、可投影、最好还可微的局部体积？

## 五、重建尝试 #3：NeRF——连续函数的高峰，结构性的慢

### 概念卡：NeRF（Neural Radiance Fields）

#### English name
**NeRF: Neural Radiance Field**

#### 中文通俗说法
神经辐射场 [Neural Radiance Field]：用神经网络（通常是 MLP）直接表示连续的 \(\sigma(\mathbf{x})\) 与视角相关颜色 \(c(\mathbf{x},\mathbf{d})\)。

#### Origin（起源）
2020 前后，人们意识到：与其纠结离散网格/点的缺陷，不如让一个连续函数拟合 volume rendering 所需的场。MLP 作为通用函数逼近器 [universal function approximator]，理论上能表示复杂场景；再用照片做 self-supervised 拟合。

#### Core idea（核心思想）

$$
F_\theta: (\mathbf{x},\mathbf{d}) \mapsto (\sigma, c)
$$

渲染：对每条像素射线做 **ray marching** + volume integration，把积分结果与真值图比 loss，反传更新 \(\theta\)。

常配 **positional encoding**（位置编码），让网络更容易拟合高频细节：

```python
# 示意：γ(x) = [sin(2^k x), cos(2^k x), ...]
# 没有它，MLP 更偏爱低频平滑函数
```

#### Why not alternatives（它解决了什么）
相对体素：连续、不绑死 \(V^3\) 网格分辨率。  
相对点云：不靠「命中点」，而是沿射线积分密度场，覆盖完整。  
相对传统 mesh：更擅长复杂外观与「拍得下来但难建模」的外观效果。

#### In 3DGS（在 3DGS 里干什么）
NeRF 是 3DGS 最重要的对照基线：  
3DGS 继承了「用可微 rendering + 多视图照片优化场景」的学习范式，但 **换掉了隐式 MLP 表示**。

#### Worked example：慢在哪里（数量级估算）

以 \(1920\times1080 \approx 2\times10^6\) 像素为例：

```text
每像素采样 ~100 点（保守）
→ 每帧 ~2×10^8 次场查询
若每次查询是 MLP 前向，算力与内存访问双重爆炸
```

更关键的是 **结构性原因**（不是单纯 kernel 没写好）：

| 公理 | 含义 |
|------|------|
| A1 | 场景编码在 MLP 权重里（implicit） |
| A2 | 渲染需要沿射线数值积分 |
| A3 | 查询任意 \(\mathbf{x}\) 几乎都要跑网络 |

**推论**：每帧海量随机位置查询 → memory-bound、难缓存成「直接可读的 3D 资产」→ 实时困难。

#### Common confusions（易混点）
1. **Instant-NGP 等加速** 大幅缩短训练/推理，但 hash grid 等仍常到不了 3DGS 那种轻松 real-time 甜区（视实现与场景而定）。  
2. **「NeRF 慢」≠「NeRF 无用」**：离线、影视、研究外观模型仍很强。  
3. **质量高来自连续表示与体积积分框架**；3DGS 也在追求高质量，但走显式 primitive 路线。

#### 生活类比（必须映射回基石）

把 **NeRF** 想成「不存地图格子，只雇一个极聪明的接线员：你报任意 3D 坐标和视线方向，他就告诉你这里密度和颜色」。

| 生活画面 | 对应基石 |
|----------|----------|
| 接线员 = MLP 权重 \(\theta\) | 隐式表示 \(F_\theta(x,d)\mapsto(\sigma,c)\) |
| 每画一像素，要沿射线问上百次 | ray marching + volume integration |
| 问得够密、学得够好 → 画质细腻 | 连续场，锯齿少，可 view-dependent |
| 但「每帧海量随机提问」本身就贵 | 结构性慢：订单是查询次数 × 网络前向 |

```text
NeRF 粗账：
  O(像素数 × 每射线采样数 × 每次 MLP 成本)
不是「CUDA 写烂了」这么简单——问题单太长
```

> 映射回基石：质量来自连续可微场 + 体积积分；慢来自隐式查询结构，不是单纯缺一个 kernel 优化。

#### 失败对照：做对 vs 做错

| 场景 | 做对 | 做错时你看到什么 |
|------|------|------------------|
| 预期帧率 | 离线/近交互合理定位 | 强行当 VR 实时 → 永远不满意 |
| 加速理解 | hash grid 等减轻查询，仍可能非 3DGS 甜区 | 以为「NeRF 优化完 = 已是 3DGS」 |
| 编辑资产 | 接受黑盒权重难挪物体 | 想「拖动椅子」→ 改权重无直接语义 |
| 诊断慢 | 先数「每帧查询次数」 | 只骂硬件 → 错过换表示的分叉 |

```text
症状速记：
  「秒级/帧」           → 经典 ray + MLP 结构账
  「画质美但交互卡死」 → 正是遗留给 3DGS 的问题
```


### 5.1 NeRF 的「得」与「失」（诚实对照）

**得**：

- 连续表示，锯齿少
- 可建模 view-dependent appearance（视角相关外观）
- 分辨率理论上随采样走

**失**：

- 推理慢（原版可到秒～几十秒/帧量级）
- 训练重
- 场景是黑盒权重，编辑、组合、流式加载都不像显式资产那么自然

**遗留问题**：

> 能否保持「可微拟合照片」的学习方式，但去掉「每帧对隐式场做海量积分查询」？

## 六、迁移应用：3DGS 的关键跳跃

### 6.1 「啊哈」时刻

两条路摆在面前：

```text
方向 A：继续优化 NeRF 家族
        （更好的编码、更少采样、蒸馏、烘焙…）

方向 B：换表示
        回到稀疏粒子世界，但给每个点真正的 3D 体积核
        并利用解析投影，避免 per-pixel ray marching 查 MLP
```

**3D Gaussian Splatting (Kerbl et al., 2023)** 选了 B，核心思想可以压成一句：

> 用大量 **各向异性 3D Gaussian** 显式表示场景；渲染时把它们 **splat** 到图像平面，做排序与 alpha blending；整条链可微，从而用照片优化 Gaussian 参数。

### 6.2 为什么是 Gaussian？（预告第 3 章，这里先给工程直觉）

结合第 0 章：

1. **连续且局部**：中心强、边缘衰减 → 填洞但不污染整图  
2. **各向异性**：Σ 可表达薄片/细杆/团块  
3. **线性变换封闭**：旋转/局部投影后仍是 Gaussian，有 `Σ' = AΣA.T`  
4. **可微**：`exp`、二次型、矩阵乘，适合 backprop  
5. **显式**：参数可读、可投影、可 frustum/tile cull，GPU 友好

对比点云：Gaussian 有 footprint。  
对比体素：只需存 N 个 primitive，不付满空间 \(V^3\)。  
对比 NeRF：不靠每像素上百次 MLP 查询，而靠 **投影 + 光栅式混合**。

### 6.3 速度差从何而来（第一性账本）

```text
NeRF 粗账：
  O(像素数 × 每射线采样数 × 每次查询成本)

3DGS 粗账：
  O(高斯数 × 投影成本 + 像素上覆盖到的高斯混合成本)
  并通过 tile culling 避免「每个 Gaussian 影响整张图」
```

数量级直觉（非常粗，只为建立感觉）：

| 方法 | 训练（量级） | 推理 | 质量（PSNR 量级，视数据集） | 表示 |
|------|--------------|------|-----------------------------|------|
| 原始 NeRF | 小时～天 | 很慢（秒级/帧常见于原设定） | 高 | 隐式 MLP |
| Instant-NGP 等 | 分钟～小时 | 更快，常仍偏交互/近实时 | 高 | 混合编码 |
| **3DGS** | 常约数十分钟量级 | **实时（可 100+ FPS 视场景/分辨率）** | 很高 | 显式 Gaussian |

常被提到的「相对原版 NeRF 上千倍加速」来自：

1. **算法结构**：去掉海量 MLP 查询  
2. **系统结构**：规则批量运算、更高 GPU 利用率（更 compute-friendly）

细节数字随硬件、实现、场景变化；**真正要记住的是结构性差异**，不是某个广告倍率。

### 6.4 3DGS 不是免费午餐：它牺牲/改写了什么？

诚实对照：

| 维度 | NeRF 倾向 | 3DGS 倾向 |
|------|-----------|-----------|
| 表示 | 隐式连续场 | 显式粒子云 |
| 实时性 | 弱（原版） | 强 |
| 编辑性 | 难 | 相对更直接（可动/可删 primitive） |
| 外观 | 天然吃 \((\mathbf{x},\mathbf{d})\) | 常用 SH 等近似 view-dependent |
| 几何边缘 | 积分场更「软硬可调」 | 需足够 Gaussian 去贴锐利结构 |
| 优化 | 连续参数 | 连续参数 + densify/prune 等离散自适应 |

所以：**3DGS 首先是实时新视角路线的巨大成功**，不是宣布 NeRF 思想死亡。后续章节（4D、feedforward 等）也会继续显示两条思想如何互相借血。

#### 生活类比（必须映射回基石）

把 **3DGS 的关键跳跃** 想成：「别再每画一笔就打电话问黑盒接线员一百次；改成在 3D 里摆好一堆可投影的软印章，一次性盖到图像上混合」。

| 生活画面 | 对应基石 |
|----------|----------|
| 从「隐式说明书」换成「显式积木堆」 | explicit 3D Gaussian primitives |
| 软印章盖下去有面积、边缘渐隐 | 连续 footprint，补点云的洞 |
| 印章在 3D 定形状，再印到照片平面 | 3D \(\Sigma\) 投影，而非纯 2D 贴斑 |
| GPU 爱「投影 + 排序 + 混合」流水线 | splat / alpha blending / tile culling |
| 印错了可以看误差回改印章参数 | 可微渲染 + 照片监督（继承 NeRF 范式） |

```text
方向 A：继续给接线员提速（更好编码、更少采样…）
方向 B：换积木——显式 Gaussian + 解析投影  ← 3DGS
```

> 映射回基石：3DGS 的跳跃在 **表示层**（隐式场 → 显式 Gaussian），渲染从海量场查询转为投影 splatting；不是「NeRF 换皮加速补丁」。

#### 失败对照：做对 vs 做错

| 场景 | 做对 | 做错时你看到什么 |
|------|------|------------------|
| 叙事 | 「换表示 + 换渲染结构」 | 「就是更快的 NeRF」→ 后续学投影/Σ 时迷茫 |
| 速度预期 | 结构性少查询 + GPU 友好 | 背「1000×」广告数字，换场景对不上就幻灭 |
| 质量预期 | 实时甜区很强，但非一切免费 | 锐利结构/强镜面仍要 densify 与外观模型 |
| 2D vs 3D | 坚持 3D 定义再投影 | 退回纯 2D splat → multi-view 再裂 |

```text
症状速记：
  「说不清为何比 NeRF 快」 → 没抓住「显式 + splat」结构差
  「当点云用又当体素骂」   → 心智还停在上一代
```

## 七、完整演化链（故事串联）

```text
Voxel
  ✓ 直觉好、查询简单
  ✗ 内存 ~ V³，空空间浪费
        │ 「只存有东西的地方」
        ▼
Point Cloud
  ✓ 稀疏 O(N)
  ✗ 0 维 → 投影空洞
        │ 「需要 3D 体积 + multi-view 一致」
        ▼
失败分支：point sprites / pure 2D splats / 重 mesh
  ✗ 假透视或不可微/不灵活
        │ 「连续场 + 可微渲染」
        ▼
NeRF
  ✓ 质量高、连续、view-dependent
  ✗ 隐式 + ray marching → 结构性慢
        │ 「显式 + 解析投影 + 仍可微」
        ▼
3D Gaussian Splatting
  ✓ 稀疏 + 连续 footprint + 实时 + 可训练
  ✗ densify 策略、大场景、强镜面等仍是研究热点
```

### 7.1 认知障碍：为什么不是更早出现？

常见两道心理墙：

1. 从 NeRF 出发的人：以为「连续 = 必须 MLP 隐式」。  
2. 从点云出发的人：试过 2D splat，觉得「加体积总会假」。

3DGS 需要同时看见：

- 稀疏显式粒子 **可以** 很强；  
- **3D Gaussian →（局部）2D Gaussian** 的数学可用；  
- 现代 GPU 光栅/排序/混合管线能把它跑到实时。

这是「图形学 splat 传统」与「NeRF 式可微多视图优化」的一次会合。

## 八、费曼摘要

> 新视角合成要你根据一堆带相机参数的照片，生成没拍过的视角。本质上，你得让计算机拥有某种 3D 场景表示，并能沿射线（或等价地）算出像素颜色。
>
> 体素最直觉，但三维网格内存立方涨，还会为空气买单。点云稀疏省钱，可点没有面积，投影尽是针孔。NeRF 用神经网络当连续场，照片一拟合，画质惊艳，但每帧要在射线上疯狂查询黑盒网络，结构上就难实时。
>
> 3DGS 的跳法是：别再每像素深挖隐式场了；把场景写成大量显式 3D Gaussian，投影成屏幕上的软椭圆，再混合成图。它继承「用渲染误差反传优化」的学习方式，但把表示换成 GPU 爱吃的显式 primitive。所以它不是细枝末节的加速补丁，而是表示层的改朝换代。

## 九、自测题（带详解）

### Q1. 只有照片没有 camera parameters，为什么几乎玩不转经典 3DGS 管线？

<details>
<summary>详解</summary>

因为训练信号是「在某个确定射线/投影模型下，渲染应等于该照片」。没有 K 与 [R|t]，像素无法对应到正确的 3D 几何关系，Gaussian 投错位置，loss 失去几何意义。pose-free 方法存在，但问题更难，不是经典 3DGS 默认设定。
</details>

### Q2. 体素内存问题是「实现不好」还是「数学必然」？

<details>
<summary>详解</summary>

在均匀稠密网格前提下是数学必然：分辨率线性↑，体素数立方↑。稀疏结构可缓解，但改变的是数据结构，不是「三维体积覆盖成本」的本质压力。
</details>

### Q3. 点云为什么加更多点仍可能有洞？

<details>
<summary>详解</summary>

洞来自 **0 维 primitive 与 2D 像素面积需求的维度不匹配**。加点提高命中率，但除非点密到近似填满投影区域（内存与渲染又恶化），否则高分辨率下仍易露点/闪烁。需要的是局部面积/体积支持，不是单纯点计数。
</details>

### Q4. 为什么说 NeRF 的慢常常是「结构性」的？

<details>
<summary>详解</summary>

因为表示是隐式的：积分路径上的采样点位置不规则，几乎都要查询网络；信息没有变成可直接投影的显式基元。工程优化能提速，但「每帧海量场查询」的订单本身还在。除非烘焙/混合表示/换表示，否则实时仍吃力。
</details>

### Q5. 3DGS 相对 NeRF 的关键跳跃，一句话怎么说？

<details>
<summary>详解</summary>

**把隐式连续场换成显式 3D Gaussian primitives，用投影 splatting 替代（或大幅避开）昂贵的 per-ray MLP volume sampling。**
</details>

### Q6. 3DGS 的 150MB 量级显存（量级直觉）可能来自什么？

<details>
<summary>详解</summary>

百万级 Gaussian 时，每点存：`μ(3)` + scale(3) + quaternion(4) + opacity(1) + 一组 SH 系数（随阶数变）……再加优化状态、缓冲。粗算几十～一百多 bytes/点很常见，故 ~1M 点到百 MB 量级合理。精确数随 SH 阶数与实现而变。
</details>

### Q7. 若应用能接受 30 秒/帧，是否还该上 3DGS？

<details>
<summary>详解</summary>

不一定。离线电影级、特殊外观、某些科学可视化可能仍偏 NeRF 家族或其他路径。3DGS 的主场是 **实时/交互 + 高质量新视角**。选方法先定约束，不要先定信仰。
</details>

### Q8. 「2D splatting」失败与「3D Gaussian splatting」成功，差在哪？

<details>
<summary>详解</summary>

差在几何定义域：2D 椭圆若只在屏幕里长出来，换视角缺少 3D 形状约束；3DGS 在世界系定义 Σ，再投影到 2D，多视图一致由 3D 参数保证（再配合优化）。
</details>
